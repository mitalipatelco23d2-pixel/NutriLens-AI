## Current release decision

The full product defined by the war-room prompt is not ready for public Android
release. Blocking product gaps are Health Connect physical consent acceptance, hydration cross-device acceptance, local-reminder device acceptance,
recipe integrations/device acceptance, authenticated production onboarding/settings acceptance, signed-build/device
acceptance, full consumer-action E2E and corrected public ten-owner production
validation. The custom YOLO service also has an unresolved legal gate.

The web foundation may remain available with conservative messaging. A broader
web launch should not advertise complete Android parity, Health Connect, local
reminders, custom recipes, reliable ten-user inference, live subscriptions or a
Play Store listing.

## Minimum path to change the decision

1. Resolve or remove the legally uncleared custom YOLO server dependency from
   the proprietary public-release path; keep distribution blocked.
2. Complete authenticated cross-device hydration and custom recipe acceptance.
   Physically accept local reminders and Health Connect and finish recipe integrations, or
   explicitly remove them from the initial release scope with owner approval
   and update all public copy.
3. Complete onboarding/DOB/optional-phone states, Settings, Android data
   controls and the required insight-first result/actions.
4. Run backend, Ruff, mypy, web lint/typecheck/Vitest/build/public E2E, Flutter
   analyze/test, Android instrumentation and security regression against one
   frozen commit; record exact results.
5. Restore the owner-controlled Edge session, then repeat the corrected public
   ten-owner test on source `34b8e21`/worker revision `0000020` and capture
   accepted/completed/failed, public acknowledgement and durable queue timing,
   quota and isolation. Worker inference, scale-up/scale-back, RAM, CPU, retry,
   OOM and latency evidence is already recorded in the 2026-09-07 report.
6. Obtain signing inputs, produce the signed APK/AAB, audit the manifest and
   dependencies, install the signed APK on the physical device and execute all
   P0 flows again.
7. Complete owner-controlled OAuth, Health/notification consent and Play Console
   actions. Submit only when the frozen signed build matches the tested build.

No GPU, larger CPU/RAM SKU, paid SMS, paid advertising or Razorpay Live change
is justified or approved by this matrix.
